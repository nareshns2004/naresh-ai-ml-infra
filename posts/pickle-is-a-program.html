Pickle is a program: loading a checkpoint is running code

A classic PyTorch .pt file isn’t data with a format. It’s a zip with a data.pkl inside, and a pickle is a program for a small stack machine whose instruction set includes “import any function” and “call it”.

Naresh Kumar · Nov 2026 · 9 min read

TL;DR
  • Two opcodes make pickle dangerous: GLOBAL / STACK_GLOBAL import a callable by name, and REDUCE calls it. Every honest PyTorch checkpoint uses both, to rebuild tensors.
  • So you can’t ban the opcodes. You can only allowlist the callables, which is what torch.load(weights_only=True) does, and allowlists in a Turing-capable format have bypasses (CVE-2025-32434).
  • safetensors removes the program: an 8-byte length, a JSON header, raw bytes. There is nothing to execute. For anything you didn’t produce, it’s the only format I’d load.

How an honest checkpoint already “runs code”

Step through the honest sample. The very first instruction is GLOBAL collections OrderedDict, then REDUCE calls it. Each tensor is GLOBAL torch._utils _rebuild_tensor_v2 applied to a storage reference that BINPERSID resolves out of the zip. Loading a state dict is a sequence of function calls chosen by the file. A malicious file just chooses different functions.

The payload sample adds one entry. Its value is GLOBAL posix system called with a shell command. On Linux, os.system pickles as posix.system, so a scanner that greps for os.system reports the file clean. The obfuscated sample goes further: under protocol 4, STACK_GLOBAL takes the module and name from two separate strings on the stack, and the argument assembles 'o'+'s' at runtime. There’s no suspicious substring to find. Only following the opcodes, as the scanner here does, reveals builtins.eval being called.

Why “safe mode” is not the fix

An allowlist is the right idea if you must read pickle. torch.load now defaults to weights_only=True, which permits only tensor-rebuilding globals. But an allowlist in front of a stack machine is a sandbox, and sandboxes get bypassed: in PyTorch 2.5.1 and earlier, weights_only=True could still be driven to remote code execution. The safe position is a format with no code path at all.

It isn’t only files

The same deserializer shows up on the wire. vLLM’s Mooncake integration moved KV-cache metadata between prefill and decode nodes with pickle over ZeroMQ sockets bound to every interface, which made it an unauthenticated RCE on the inference fabric. And Wiz ran code inside Hugging Face’s inference infrastructure simply by uploading a pickle model. It’s the rule I’m holding kvwire’s control path to as it’s built: KV transfer is a network service, so its metadata gets a fixed schema and a code-free encoding.

What I’d enforce

  • Ingest: anything from outside the org is converted to safetensors in an isolated, network-less sandbox, or rejected.
  • Produce: checkpoints are written as safetensors (or a tensor-only sharded format), hashed per shard, and signed. Restores verify before reading a byte.
  • Wire: no pickle on any socket, internal or not. Fixed schemas, authenticated peers, private interfaces.
  • Legacy: where pickle is unavoidable, weights_only=True on a current PyTorch, inside a sandbox, with an opcode scan like this one in CI as a tripwire, not a guarantee.

Model & assumptions

  • The samples were produced by Python’s own pickle module, with stand-in classes that emit the same GLOBAL names a real torch.save data.pkl contains (protocol 2; protocol 4 for the obfuscated one). They were generated without ever being unpickled. The payload commands are inert strings pointing at attacker.example.
  • The disassembler implements the opcodes these files use, plus the common protocol 0–5 opcodes. It simulates the stack symbolically, with no evaluation. Unknown opcodes stop the walk and are reported.
  • The allowlist is a small subset in the spirit of weights_only: collections.OrderedDict, torch._utils._rebuild_tensor_v2, torch._utils._rebuild_parameter, torch.Size and the torch.*Storage types. It is illustrative, not PyTorch’s exact list.
  • The “naive grep” scanner looks for os.system, subprocess, builtins.eval, builtins.exec and __builtin__ as substrings, the way a quick blocklist would.
